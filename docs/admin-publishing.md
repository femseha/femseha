# النشر المباشر من لوحة الإدارة (/admin) — Simple Admin + AI Direct Publishing

> **القاعدة:** إدخال البيانات → توليد المقال (AI) → **نشر مباشر**، أو كتابة المقال يدوياً → **نشر مباشر**.
> **لا يوجد Review ولا Approval ولا Draft workflow** — لا أي مرحلة بين إنشاء المقال والنشر.
> الموقع العام والـ SEO والتصميم الحالي **FROZEN** — هذه الميزة تخص `/admin` وخط النشر فقط.

## 1) الأقسام الثلاثة في /admin

1. **توليد مقال بالذكاء الاصطناعي** — الحقول: عنوان المقال، الكلمة المفتاحية الرئيسية، كلمات مفتاحية إضافية (اختياري)، الدولة/السوق (اختياري)، تعليمات المقال (اختياري)، صورة المقال، وزر واحد: **«توليد ونشر المقال»**.
2. **إضافة مقال (يدوي)** — الحقول: العنوان، الكلمة المفتاحية الرئيسية، كلمات إضافية (اختياري)، الدولة (اختياري)، الصورة، محتوى المقال، Meta Description، Slug، وزر **«نشر المقال»**. نفس النموذج يُستخدم لـ **«تعديل»** مقال منشور من القائمة (الـ slug مقفل أثناء التعديل حمايةً للروابط، ويُسجَّل `modifiedDate` حقيقي).
3. **قائمة المقالات** — العنوان | الكلمة المفتاحية | الدولة | التاريخ | تعديل | فتح المقال، مع بحث بسيط.

### الدول/الأسواق المدعومة (اختيارية — يمكن تركها «عام»)

🇸🇦 السعودية • 🇦🇪 الإمارات • 🇰🇼 الكويت • 🇧🇭 البحرين • 🇶🇦 قطر • 🇴🇲 عُمان

المصدر الوحيد: `src/data/countries.json` (تقرأه الواجهة وخط النشر معاً). الدولة تُحفظ في سجل المقال كحقل `country` اختياري جديد — المقالات القديمة بلا حقل = «عام»، ولا يتغير عرضها إطلاقاً.

## 2) المعمارية (نفس بنية المشروع الحالية — بلا خادم جديد)

الموقع Static SPA على Vercel بلا backend، لذا يتم النشر **عبر المستودع نفسه** وخط النشر القائم:

```
/admin (المتصفح)
  │ 1. فحص فوري في المتصفح (منع Cannibalization + الجودة + السلامة) — src/lib/article-rules.ts
  │ 2. (اختياري) ضغط صورة المقال ورفعها إلى public/images/uploads/ عبر GitHub Contents API
  │ 3. حفظ طلب النشر: admin/requests/<id>.json عبر GitHub Contents API
  │ 4. تشغيل سير العمل القائم .github/workflows/auto-publish.yml عبر workflow_dispatch (دون أي تعديل عليه)
  ▼
GitHub Actions (node scripts/generate-article.mjs)
  │ 5. يكتشف الطلبات المعلقة في admin/requests/ ويستدعي scripts/admin-publish.mjs
  │    • AI: توليد Gemini (GEMINI_API_KEY من Secrets) بنفس قواعد الخط الآلي + سياق الدولة/التعليمات
  │    • Manual: المقال كما كُتب
  │    • الفحوصات الإلزامية: الجودة (≥1400 كلمة، عنوان 20–75، وصف 100–170)، السلامة الطبية،
  │      حارس YMYL التجاري، منع تنافس الكلمات المفتاحية (نفس findCannibalization)، slug فريد،
  │      روابط داخلية صالحة، وصف/عنوان غير مكررين
  │ 6. الحفظ بالطريقة الحالية: src/data/articles.json + توليد public/sitemap.xml (نفس المولّد)
  │    + قسم الاستشارة الرسمية والروابط الداخلية عند غيابها (نفس finalizeContent)
  │ 7. حذف الطلب الناجح / تعليم المرفوض (status:"failed" + السبب) ثم git push إلى main
  ▼
Vercel يبني من main → المقال منشور (اللوحة تعرض رابط المقال عند اكتمال التشغيل)
```

- **نجاح** = الطلب اختفى من `admin/requests/` ويظهر رابط المقال في اللوحة.
- **رفض** = الطلب يبقى معلَّماً بالفشل مع السبب الحرفي (تعرضه اللوحة، ويمكن حذفه وتصحيحه وإعادة الإرسال). الرفض الآلي ليس «مراجعة» — لا يتدخل أي إنسان، ولا يُنشر ما فشل.
- **طلب معلق** (انقطاع شبكة/فشل تشغيل Actions) يُلتقط تلقائياً في أول تشغيل تالٍ (يدوي أو مجدول).

## 3) الأمان (AI Security)

- `GEMINI_API_KEY` **لا يصل للمتصفح أبداً** — يوجد حصراً في GitHub Secrets ويُستخدم داخل Actions فقط (كما هو قائم).
- اللوحة تحتاج **توكن GitHub شخصي (PAT classic بصلاحية `repo`)** يدخله المالك مرة واحدة ويُحفظ في `localStorage` **في متصفح المالك فقط** — لا يُوضع في أي ملف كود أو مستودع، ولا يُرسل إلا إلى `api.github.com`. زر «قطع الاتصال» يحذفه.
- كلمة مرور `/admin` ونظام الدخول الحالي **كما هي دون أي تغيير**.
- صفحة `/admin` ما زالت `noindex, nofollow` وبلا canonical ومحجوبة في `robots.txt` وخارج الـ sitemap (دون تغيير).

## 4) قواعد المحتوى الطبي والسلامة (مطبّقة على AI واليدوي معاً)

يُرفض تلقائياً أي محتوى يتضمن: تعليمات شراء أدوية، أسماء/أرقام بائعين، روابط شراء، أسعار أدوية (بأي عملة تشمل عملات الخليج)، جرعات أو تعليمات استخدام رقمية، وسائل تواصل (هاتف/واتساب)، وعود نتائج مضمونة، أسماء صيدليات أو جهات صرف. خصوصاً في مواضيع Cytotec/Misoprostol/سايتوتك/أدوية الإجهاض — المحتوى تثقيفي وآمن فقط، مع التوجيه الدائم للتقييم الطبي المباشر.

كما يمنع النظام تلقائياً إنشاء صفحات Doorway/مكررة: أي موضوع يتنافس مع مقال منشور (نفس الكلمة المفتاحية، تغطية ≥60%، أو تشابه عنوان >75%) يُرفض مع ذكر المقال المتنافس — بنفس منطق خط النشر الآلي القائم حرفياً.

## 5) SEO للمقالات الجديدة (نفس القواعد الحالية — دون تغيير SEO القديم)

كل مقال جديد يحصل تلقائياً على: slug فريد بصيغة `a-z0-9-`، عنوان ووصف فريدين، H1 واحد (عنوان المقال في ArticleView القائم)، H2/H3 منظمة من تنسيق المحتوى، إدخال تلقائي في `sitemap.xml` (نفس المولّد الموحّد)، canonical ذاتي وArticle/FAQ Schema (من ArticleView القائم دون تعديل)، روابط داخلية («اقرئي أيضاً» + قسم الاستشارة)، ومنع تنافس الكلمات. حقلا `country` و`secondaryKeywords` الجديدان **بيانات فقط** — لا يُحقنان في أي وسم meta ولا يغيّران أي قالب SEO قائم.

## 6) التشغيل والاختبار

```bash
npm run admin:selftest                      # اختبار خط لوحة الإدارة كاملاً دون Gemini ودون لمس الملفات الحقيقية
node scripts/generate-article.mjs --self-test   # اختبار الخط الآلي القائم (كما هو)
npm run build && npm run typecheck
npm run seo:validate && npm run verify:ssr && npm run audit:indexing
```

## 7) ما لم يتغير (FROZEN)

`.github/workflows/auto-publish.yml` (كما هو — استُخدم `workflow_dispatch` الموجود فيه أصلاً)، كل صفحات الموقع العام وقوالبه و`ArticleView` والهيدر/الفوتر والألوان والخطوط والصور الحالية، `index.html` و`robots.txt` ومولّد الـ sitemap وأدوات التحقق، `src/data/articles.json` و`content-map.json` و`keyword-map.json`، الجدولة اليومية والسقف (3 مقالات/يوم) لطابور خطة المحتوى، ونظام دخول `/admin`.

## 8) ملفات الميزة

| الملف | الدور |
|---|---|
| `src/pages/AdminPage.tsx` | اللوحة: دخول (كما هو) + الأقسام الثلاثة + حالة النشر |
| `src/components/admin/*` | النموذجان، القائمة، الربط، حالة النشر، الطلبات المحفوظة |
| `src/lib/article-rules.ts` | مرآة المتصفح لقواعد الفحص (فحص فوري قبل الإرسال) |
| `src/lib/github-publish.ts` | عميل GitHub REST + تنسيق النشر المباشر (طلب → تشغيل → نتيجة) |
| `src/data/countries.json` | الدول الست (مصدر وحيد للواجهة والخادم) |
| `scripts/admin-publish.mjs` | خط النشر المباشر (AI + يدوي + تعديل) — يستورد قواعد الخط الآلي نفسها |
| `scripts/generate-article.mjs` | +exports وإعادة استخدام، واكتشاف طلبات اللوحة قبل الطابور (السلوك المجدول دون تغيير) |
| `src/data/types.ts` | +حقلين اختياريين في `ArticleRecord`: `country` و`secondaryKeywords` |
