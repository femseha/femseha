## Confirmed technical findings on main
1. SSR route tree is wrapped in React.lazy / Suspense in src/App.tsx. The separate SSR renderer uses renderToString; renderToString does not wait for suspended lazy components. A non-empty HTML check is insufficient to prove content is present.
2. scripts/prerender.mjs only removes title and canonical from index.html. Existing description, robots, OG, Twitter, and JSON-LD can remain alongside route-specific metadata.
3. Canonical path generation removes a trailing slash for non-root paths, while sitemap contains only root with a trailing slash. The intended canonical URL form must be explicitly selected and verified before changing redirects or sitemap URLs.
4. ClusterPage.tsx uses CLUSTER_PAGES['/cytotec-saudi-arabia'] as fallback for any unknown cluster path. Unknown routes may therefore render Saudi page content instead of a genuine not-found response.
5. src/data/articles.ts silently deduplicates all article sources using first-match wins.
6. scripts/generate-sitemap.mjs silently skips duplicate slugs and only warns.
7. scripts/seo-validate.mjs deduplicates raw articles before validating duplicate slugs, making its later duplicate check ineffective.
8. scripts/ssr-verify.mjs checks output length and a small set of snippets, but does not assert per-route H1, title/description/canonical uniqueness or absence of template metadata duplicates.
9. index.html includes a non-generic, page-specific home description and schema objects (MedicalOrganization and Physician), which should not be indiscriminately stripped without recreating equivalent trustworthy home metadata.
10. Existing city pages are generated by a shared template with city substitutions. Their indexability and distinct value require a page-by-page content and Search Console review; do not mass-delete or alter them.
